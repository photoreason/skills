# Portfolio Site Builder

Help photographers make a home for their work. Preserve their edit, sequence,
voice, and existing choices. Standalone photo sequencing is a separate workflow.

## First question: conversation language

Before asking about costs, resources, or tools, ask:
**“Which language would you like to chat in? English / 日本語 / 简体中文”**
Use `en`, `ja`, or `zh-hans` accordingly. If they already explicitly chose a chat
language, use it without asking again. This choice does not determine website
languages, audience, currency, or hosting. Continue in the chosen language.

## How to work

- **Guide mode (default):** prepare the files and explain the next browser step;
  the user handles account screens. Ask only for missing information needed now.
- **Computer-use mode:** offer help with difficult screens only if the host
  actually exposes suitable browser/desktop tools. After the user grants control,
  read [computer-use.md](references/computer-use.md). A skill installation does not
  add mouse control. Honor an existing grant and return control when requested.
- Both modes follow the workflow below. Draft and assemble what your tools allow;
  keep sign-in, verification, and payment details out of chat. Computer control
  alone does not authorize purchases, DNS changes, or publication.
- Load only the reference needed for the current stage and chosen route. Do not
  read every reference, source file, or example up front. Copy the template as files;
  inspect only files relevant to the requested edits. Keep checkpoints brief and
  retain known choices instead of repeating the intake.

## 1. Costs

Read [costs.md](references/costs.md). Ask for currency and budget if unknown;
explain assistant, hosting, domain, renewal, and optional add-on costs separately
using current official terms.

Recommend **the included template on Cloudflare Pages**, also for mainland China
audiences. Offer **Squarespace** for a paid visual editor; it uses the template
as a blueprint, not an HTML import. Honor a platform already chosen. Audience
location calls for real access testing, not automatic substitution with 上线了 or
another regional builder. Do not promise mainland connectivity without evidence.

## 2. Resources

Gather photographs grouped and ordered by project, name/bio, project notes,
optional captions, public contact details, desired website languages, and any
existing domain/registrar. Draft missing text for review without inventing credits.

Read [curation.md](references/curation.md) when preparing content. Prefer web-sized
**WebP or JPEG** copies, keep originals, and review quality before publishing.
For a domain, read [domains.md](references/domains.md): Namecheap, GoDaddy,
Squarespace Domains, Cloudflare Registrar, and Tencent Cloud are options. Keep
existing registrations; registrar and host can differ. A custom domain is optional.

## 3. Build

For Cloudflare, copy `templates/portfolio/` and follow
[template-guide.md](references/template-guide.md). Fill the content and images;
keep its artistic, monochrome, image-first design, stack/grid layouts, and sequence.
Change design only when requested. Use only approved content and website languages.
Private placeholders must be replaced or removed before publication.

For Squarespace, instead read
[track-visual-builder.md](references/track-visual-builder.md) and recreate the
structure in its editor. Explain material limitations before paid commitments.

## 4. Preview

Show a real preview, check phone and desktop layouts, requested languages, image
order/loading, gallery/zoom/keyboard controls, captions, credits, contact links,
and page metadata. Invite revisions and verify them. Without preview tools, hand
over a local preview and specific checks; report unverified behavior honestly.

## 5. Publish

Match the concrete address and paid/public actions to existing authorization.
For Cloudflare read [deploy-static.md](references/deploy-static.md); for Squarespace
use its route above. Preserve unrelated DNS/email records. In computer-use mode,
return control for sign-in, verification, and payment entry, then resume.

Open the live address in a fresh session. For mainland audiences, arrange a check
from the intended network; mark it pending if unavailable. If access fails, explain
the evidence and agree on a next step rather than silently replacing the host.

## 6. Handover

Provide the URL, files or editing access, credits, known recurring costs, and
short instructions to update a photo or project, identifying what publishes changes.
Use the [launch checklist](references/curation.md#launch-checklist); do not call
files or a successful upload a verified launch. Share/promote only when asked.
If a step fails, preserve progress, explain it, and continue from the last useful
checkpoint. Stores, client proofing, and unrelated account work are separate scope.
