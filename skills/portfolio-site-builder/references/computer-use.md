# Taking over a difficult step

Read this when the user chooses Computer-use mode. The portfolio stages, costs,
preview requirement, and publishing choice remain the same as Guide mode.

## Start with the available capability

Check the host's exposed browser/computer tools. A browser-only tool can work in
web tabs; it may not control a desktop file picker. Full desktop access is a
separate capability. Use the most limited tool that can complete the agreed step.
If neither is available, explain that limitation and guide the user through it.
Do not install remote-control software or change system permissions on your own.

The user grants control through the host's own permission flow. Tell them the
concrete next task, such as "I can upload the preview files to your Cloudflare
project." If their existing grant covers it, proceed; don't repeatedly ask them
to approve routine clicks. Keep this work inside the agreed site, account, and tab.

## Work with a visible checkpoint

1. Look at the current screen. Confirm the correct site/project and account
   before changing it; don't rely on stale screen coordinates or remembered UI.
2. Carry out the agreed task. Good handoff points include filling a builder's
   pages, uploading the prepared site, reviewing domain records, and checking a
   deployment. Read current provider instructions when the UI differs.
3. For sign-in, two-factor codes, CAPTCHA, or payment entry, return control to
   the user. Resume once they finish; never request secret values in chat.
4. Before a purchase, domain transfer, changing existing DNS, or public release,
   confirm the concrete change unless it is already covered by the user's
   authorization. A grant of mouse access alone does not authorize these actions.
5. Verify the visible result and open the preview/live site where relevant.
   Report what changed and the next step. Stop or return control immediately
   when the user asks, when a tool permission ends, or when an unexpected state
   makes the intended action unclear.

Keep private resources out of the published site unless supplied for publication.
Do not browse unrelated tabs, files, messages, or stored credentials. Preserve
existing domain/email records when adding website records. If control fails,
explain the last completed step and continue with a short guided instruction.
